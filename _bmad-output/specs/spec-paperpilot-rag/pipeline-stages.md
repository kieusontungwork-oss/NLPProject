# PaperPilot: Pipeline Stages & Ablation Ladder (companion to SPEC.md)

## Pipeline

```
User research question
        |
        v
[ Query processing ]---------> (optional) Query rewriting / expansion (local LLM)
        |                       mode-specific routing:
        v                         - HyDE: embed the hypothetical answer passage,
   +----+----+                      DENSE leg only (BM25 always sees the raw query)
    |         |                     - multi-query: 3-5 variants to BOTH legs,
    v         v                      variant rankings pooled (RRF) per leg
  BM25      Dense (FAISS)
  (sparse)  (MiniLM / bge-m3)
    |         |
    +----+----+
         |
         v
  Section-aware weighting (boost abstract/method/results/conclusion, optional;
  applied to leg scores BEFORE fusion so it shapes the candidate pool)
         |
         v
  Hybrid fusion (RRF, k=60)
         |
         v
  Cross-encoder re-rank (top-50 -> top-10, optional)
         |
         v
  Evidence pack: top-k passages + metadata (paper, section, year, link)
        |
        v
  Generator (Ollama local, pluggable) -- conditioned ONLY on evidence pack
        |                                  + insufficient-evidence path: 2-stage gate
        v
   +----+----+
   |         |
   v         v
 Answer     Numbered citations
 (with       -> paper title + passage + link
  self-check
  flag)
```

Every optional stage is a config flag (see stack.md swap rule) so the ablation matrix is generated by running the same harness with flags toggled.

**Why section-aware weighting sits before fusion:** applied after the top-50 → top-10 re-rank cut it could only reorder the 10 surviving chunks, leaving P@10/Recall@10 unchanged, so E6 would be a near no-op. As a pre-fusion boost it shapes each leg's ranking and thus which 50 chunks the cross-encoder sees (recall prior at first stage, semantic precision at re-rank). Note: the chunk `header_prefix` already gives BM25/embeddings implicit section context; this flag is the explicit rank prior. Fallback if E6 gains are weak: post-rerank score blend (`rerank_score + λ·section_weight` on the top-50) as an extra ablation row.

**Insufficient-evidence trigger (defined, testable):** a two-stage gate, both stages config-flagged.
1. *Score gate (pre-LLM, cheap):* when rerank is on, if the best cross-encoder score is below threshold `τ` (calibrated on a ~50-question dev slice, never a hard-coded default), return the canned "not enough evidence in the library" response without calling the generator.
2. *Generator-declared:* the prompt instructs the model to emit an `INSUFFICIENT_EVIDENCE` marker when the passages do not support an answer; the marker maps to the canned response. This is the primary trigger in rerank-off configs and the semantic backstop everywhere.

Rejected: thresholding dense-leg cosine; in a hybrid+rerank pipeline the dense leg is not the final signal (BM25-strong queries would misfire), and cosine values are model-dependent (MiniLM vs bge-m3), so a fixed 0.25 wouldn't survive the planned embedding swap. Acceptance test on the unanswerable slice: gate fires on ≥80% of unanswerable questions with ≤10% false-fire on answerable (both rates reported via `make eval`).

## Ablation ladder (the project's core experiment: Q3 & Q5)

| # | Configuration | Proves |
| --- | --- | --- |
| E1 | BM25 only | Sparse baseline |
| E2 | Dense only | Semantic baseline |
| E3 | BM25 + dense (RRF) | Hybrid gain |
| E4 | E3 + cross-encoder re-rank | Re-ranking gain |
| E5a | E4 + HyDE (hypothetical doc embedded, dense leg only; BM25 keeps raw query) | Rewriting gain, embedding-side |
| E5b | E4 + multi-query (variants to both legs, RRF-pooled per leg) | Rewriting gain, lexical + embedding |
| E6 | best(E5a, E5b) + section-aware weighting | **PaperPilot's proposed system** |
| E6Δ (diagnostic) | E3 + section-aware weighting (no rerank, no rewrite) | Section-aware gain without the reranker overshadowing it |
| E7 (answer-side, Q5) | E6 ± faithfulness self-check | Generation innovation gain |

Metrics per run: P@5/P@10, Recall@10/100, MRR, nDCG@10 on qrels; downstream answer quality (RAGAS) for the generation configurations; p50/p95 latency per stage. Each retained innovation needs ≥2 documented "failed before / works now" queries.

**Ladder order ≠ pipeline order.** Each row toggles flags in one fixed architecture: when section-aware weighting is on, it always applies pre-fusion (see diagram); enabling it at E6 does not move it downstream. Components are added standard→novel so the ladder ends on the proposed system, and E3 stays the course-designated hybrid baseline (comparable across groups). E6Δ separates "overshadowed by the reranker" (E6Δ healthy, E6 small) from "no signal" (both weak). If E6Δ is strong but E6 is not, the λ-blend fallback above is the fix to try.

## Knowledge-base schema

Per paper: `arxiv_id, title, authors[], year, abstract, sections{...}, source_link, license`.
Per chunk (JSONL, one per line): `chunk_id, arxiv_id, section_name, section_rank, text, n_tokens, header_prefix` (title + section header prepended for context). Dedup by content hash before chunking; `kb_stats.json` = {papers, chunks, words, types, chunk-size histogram}.

## Chunking design (graded design choice; document it in the report)

- Structure-aware split at section boundaries from the dataset's parsed structure (not fixed-length hack).
- Target 256-512 tokens per chunk, ~15% overlap, abstract kept as its own chunk.
- Header prefix (paper title + section name) on every chunk so embeddings and BM25 both see context.
- Alternatives (fixed 512 no-overlap, no header prefix) run as ablation rows in E-ladder style if time permits.

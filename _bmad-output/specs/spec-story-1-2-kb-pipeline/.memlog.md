- (capability) CAP-1: one-command KB rebuild — make kb acquires the verified source, joins arXiv metadata, cleans, dedups, chunks structure-aware, and emits data/kb/papers.jsonl + chunks.jsonl + kb_stats.json deterministically; success = full-corpus run with papers>=10k, zero null-metadata papers, chunk band 256-512, identical chunk_ids on rebuild.
- (decision) Source pinned by Week-0 spike: HF scientific_papers arxiv split via official S3 zip (~3.5GB, train.txt JSONL member); streamed acquisition, no HF datasets loader (script loader broken per spike).
- (decision) Record schema: article_id, article_text[], abstract_text[], sections[][], section_names[], labels — chunking inputs ready-made; 99% of papers have >=2 named sections (5.6/paper).
- (decision) Metadata join: gs://arxiv-dataset/metadata-v5/arxiv-metadata-oai.json (4.5GB JSONL, public) fills title/authors/year/categories/license; dataset ids re-slashed pre-2007 (nlin0608019 -> nlin/0608019) and metadata ids stripped of version suffix (0704.0001v2 -> 0704.0001) before matching.
- (decision) cs.* category filter via the same join; expected ~16k pre-clean (spike: 7.5% of split); if <12k pre-clean, widen to all arXiv categories and record composition + widened flag in kb_stats.json.
- (decision) Chunking (graded design choice): structure-aware section-boundary split, 256-512 token band, ~15% overlap on oversized sections, abstract as its own chunk, header_prefix = title + section name on every chunk; section-less papers (1%) become a single 'body' section.
- (decision) chunk_id minted ONLY by paperpilot.core.ids.chunk_id per AD-2 (16-hex SHA-1 over arxiv_id+US+section_name+US+normalize(text), NFC + whitespace collapse); stored chunk text is the normalized text so id and text always agree.
- (decision) Artifact classes per AD-5: make kb writes only class 2 (data/raw/, data/kb/); data/eval/ (class 1) untouched; outputs atomic via tmp+os.replace; rebuilds are wholesale, never patched.
- (constraint) Tests are offline: synthetic mini-corpus fixtures under tests/, no network in pytest; the full-corpus make kb run is the acceptance run, not a test.
- (constraint) Bounded RAM: stream-parse the 3.5GB train.txt and 4.5GB metadata JSONL line-by-line; never load either fully into memory.
- (constraint) No paper is ever emitted with null metadata — a missing metadata row drops the paper (citation resolvability 100%); dropped/duplicate/malformed counts are recorded in kb_stats.json, never hidden.
- (constraint) English-only corpus: clean stage drops non-English papers via a documented heuristic (no new heavy deps); counts reported.
- (constraint) Bootstrap deps minimal and pinned: pydantic 2.14.1 (+ pytest/pyyaml dev) in pyproject.toml + committed uv.lock; heavy deps (sentence-transformers, faiss) join in their own stories.
- (decision) Token count for the chunk band is a documented estimator (words x 4/3, single-sourced in core) — no model tokenizer at KB time; swapping to a real tokenizer later is a config-visible change, not a silent one.
- (decision) Robustness: malformed JSONL lines are skipped + counted (warn), never crash the whole build; dedup by SHA-256 over normalized full text pre-chunking, keep first occurrence in file order.
- (decision) kb_stats.json fields: papers, chunks, words, types, chunk-size histogram, year_min, year_max, year histogram, category composition (cs.* and AI/ML/NLP shares), plus provenance (source url, filter mode, dropped_no_metadata, duplicates, malformed_lines, non_english_dropped).
- (note) Non-goals: no retrieval/indexing/embedding (stories 1.3+), no eval harness, no GCS-PDF fallback activation, no chunking-variant ablation rows (spine Deferred), no AI/ML/NLP-only subcollection export (composition stats only).
- (assumption) Acceptance run executes on this laptop: ~8GB download+extract headroom needed, 289GB free — fits.
